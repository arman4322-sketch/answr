The objective is simple: by the end of the window, the buyer has full ownership and control of every asset, understands how the platform is built and operated, and has been walked through the steps to activate it. The detailed technical steps live in the accompanying HANDOFF.md (activation guide) and LAUNCH_ROADMAP.md; this plan is the wrapper that sequences them and defines roles, timing, and support.

2. How the platform is built and supported

An important, transparent note that shapes this handover — and that a technical buyer should understand up front:

Answr was built using an AI-assisted development workflow (Claude Code). The Seller is a product owner and operator, not a hands-on software engineer: the platform is directed, changed, and operated through that AI-assisted workflow rather than by hand-writing code. This is why the codebase is unusually well-documented and consistent.

Practically, for the handover this means:

  • The Seller will walk the buyer through every step that needs to happen to activate the platform, on calls, and help get those steps done — using the same AI-assisted workflow the product was built with.
  • The Seller does not provide deep, hands-on engineering consulting (architecture debates, manual debugging). Those are best handled by the buyer's own technical resource — who can, likewise, use an AI-assisted workflow to operate and extend the platform efficiently.
  • The full documentation set is written precisely so the platform can be operated and extended this way.

3. Handover timeline

A phased two-week window (~20–25 hours of Seller time, over email and scheduled calls). Timing is indicative and can flex to the buyer's pace.

Phase 0 — Pre-close preparationBefore / at close
  • Confirm the asset list and the transfer method (§4).
  • Buyer sets up the accounts they'll own into: a GitHub account and a Vercel account.
  • Schedule the handover calls across the two-week window.
Phase 1 — Access & asset transferWeek 1, days 1–3
  • Transfer the GitHub repository and the useanswr.com domain to the buyer (§4).
  • Hand over the brand assets, design files, and the full documentation set.
  • Buyer confirms they can access everything and deploy the codebase to their own Vercel account.
Phase 2 — Guided activationWeek 1, days 3–7
  • On calls, walk through the activation checklist together (per HANDOFF.md): set the app secrets, connect a storage key, add the provider API keys, and verify each integration.
  • Turn on the nightly sampler and confirm data flows.
  • The Seller helps execute these steps via the AI-assisted workflow; the buyer's technical resource can drive in parallel.
Phase 3 — Knowledge transferWeek 2, days 8–11
  • Walk through how the platform is structured and operated, using the Technical Documentation and Platform Overview as the guide.
  • Review the remaining build items to go fully live (per LAUNCH_ROADMAP.md) so the buyer's technical resource can plan them.
  • Cover the day-to-day: how to deploy, where things live, and how to make changes through the AI-assisted workflow.
Phase 4 — Wind-down & completionWeek 2, days 12–14
  • Address any open questions and confirm the completion criteria (§7) are met.
  • Final Q&A; confirm the buyer is self-sufficient.
  • Transition to the post-handover arrangement (§8).

6. Issues & fixes during the window

If a genuine issue surfaces while activating during the handover window, it is addressed through the same AI-assisted workflow (Claude Code) the platform was built with — run by the Seller, or by the buyer's technical resource. This keeps fixes fast and consistent with how the codebase is maintained, rather than depending on hand-coding. New features and the remaining launch build (per the launch roadmap) are the buyer's, not part of the handover.

7. Communication & completion criteria

Communication

Primary support is by email and scheduled calls, across the two-week window, up to approximately 20–25 hours of Seller time. Calls are booked in advance around the phases above.

Completion criteria (definition of "done")

  • All assets and accounts (repository, domain, brand, docs) are transferred to and accessible by the buyer.
  • The buyer has deployed the codebase under their own hosting account.
  • The buyer has been walked through the full activation checklist and understands each step.
  • The buyer has received the knowledge-transfer walkthrough of the architecture, operation, and remaining build.
  • Open questions within scope have been addressed.

8. After the handover

Once the two-week window is complete and the completion criteria are met, the formal handover concludes. The Seller remains available for paid consulting on an as-needed basis thereafter — arranged separately by agreement — so the buyer has continuity if a question comes up later. Ongoing operation, development, and growth of the platform rest with the buyer.
